# JeevanSetu Design System

## Design direction
Trustworthy, calm, accessible, modern, human and healthcare-focused. Avoid a generic AI-startup appearance.

## Visual principles
Clear hierarchy, high readability, large touch targets, simple language, minimal decoration, strong status indicators, consistent spacing and responsive layouts.

## Color direction
Use a restrained healthcare blue/teal primary family, neutral surfaces, and clear green/amber/red/blue status colors. Avoid excessive gradients.

## Typography
Clean sans-serif, readable body text, strong but restrained headings. Support Hindi, Marathi and English.

## Reusable components
Button, Input, Select, Textarea, Card, Badge, Alert, Modal, Dialog, Table, Tabs, Sidebar, Navbar, Breadcrumb, EmptyState, LoadingState, ErrorState, StatusTimeline, ResourceCard, HospitalCard, SchemeCard, NGOCard, ReferralCard, AIRecommendationCard, DashboardMetricCard.

## Landing page
Hero → Problem → How it works → Core capabilities → Patient journey → PHC capabilities → AI/automation → Trust/safety → CTA → Footer.

## Patient dashboard
Prioritize active case, AI recommendations, relevant resources, referral status, assistance requests, documents and notifications.

## PHC dashboard
Prioritize today's activity, medicine stock risk, pending referrals, service activity and alerts.

## Admin dashboard
Show users, cases, referrals, PHC alerts, medicine alerts, service anomalies, feedback trends and verification queue.

## Referral UI
Use a clear timeline:
Created → Notified → Accepted → Hospital Reached → Treatment Started → Completed.

## AI UI
AI should look like assistance, not medical authority. Show what was found, recommendations, why they may be relevant, next steps and caution. Let users inspect the underlying verified resource.

## Forms
Clear labels, required fields, inline validation, preserved input on errors and helpful messages.

## Accessibility
Keyboard access, readable contrast, screen-reader labels, large touch targets, responsive design and simple language.

## Responsive
Design for mobile, tablet and desktop. Patient flows should work well on low-end/mobile devices.

## States
Every data-driven page has loading, empty, error and success states.

## Maps
Maps are supportive. Always show name, address, phone, service and available directions/action.

## Consistency
All roles should feel like the same product.
